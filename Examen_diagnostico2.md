Instrucciones: Responde de manera clara y concisa a cada una de las siguientes preguntas abiertas. El propósito de esta evaluación es medir tus conocimientos previos en Ingeniería de Software.

1. Metodologías: ¿Cuál es la diferencia principal entre una metodología de desarrollo tradicional (como Cascada) y una metodología ágil (como Scrum) frente a los cambios en los requisitos?
Las metodologías agiles como su nombre lo dicen permiten mayor eficiencia en la realización de entregables como también identificar problemas con el desempeño del equipo, los scrum dailys ayudan mucho a saber el estado del entregable y si todo fluye acorde a lo establecido o alguien tiene problemas.

2. Requerimientos: Explica la diferencia entre requerimientos funcionales y no funcionales, dando un ejemplo de cada uno aplicable a una plataforma web.
Un requerimiento funcional es un servicio o modulo que el sistema necesita, por ejemplo: yo como usuario quiero iniciar sesión con mi usuario y contraseña
Un requerimiento no funcional puede ser algo añadido a ciertos módulos, por ejemplo: que una dashboard de gestión cargue la información en cierto tiempo.

3. Arquitectura: Describe el modelo Cliente-Servidor y explica brevemente cómo se comunican el frontend y el backend en una aplicación web moderna. 
El cliente manda a llamar funciones que existen en el servidor, por ejemplo: obtener los alumnos inscritos en sistemas. Esto ayuda a hacer mas ligera la carga en la parte del usuario, si hacemos llamados al backend en el cliente se haría muy pesado y lento las respuestas del mismo.

4. Bases de Datos: ¿En qué escenarios recomendarías utilizar una base de datos relacional (SQL) frente a una no relacional (NoSQL) para el almacenamiento de datos en una aplicación? 

5. APIs: ¿Qué es una API REST y qué papel fundamental juega en la integración entre una aplicación móvil y los servidores (backend)?
Es una forma de que ciertas aplicaciones se comuniquen entre si mediante el uso de peticiones como pueden ser get post.

6. Control de Versiones: Explica la importancia de utilizar Git en un equipo de desarrollo de software y describe brevemente qué es un "merge conflict" (conflicto de fusión). 
En mi experiencia, tuvimos conflictos y caídas debido a que se hacían commits con una versión antigua del proyecto, lo cual tumbaba varios módulos. El control de versiones nos permite regresar a la versión anterior al commit y que todo vuelva a funcionar, puede ser que se tenga que hacer de nuevo el trabajo, pero es mejor que tener que arreglar todo el proyecto. Los conflictos se suelen dar porque algunos integrantes modifiquen el mismo modulo, se puede hacer el merge pero hay que revisar detenidamente que se modifico y si se pueden combinar sin problema.

7. Pruebas: ¿Qué son las pruebas unitarias (unit testing) y por qué son cruciales para asegurar la calidad del software antes de su paso a producción?
Son para asegurarse de que ciertas funciones o bloques funcionen correctamente y en el caso de que no estén funcionando, saber cuáles presentan fallas.

8. POO: Define los conceptos de encapsulamiento y polimorfismo de la Programación Orientada a Objetos, y menciona cómo ayudan a crear un código más mantenible. 

9. Patrones de Diseño: ¿Qué es el patrón de arquitectura Modelo-Vista-Controlador (MVC) y cómo ayuda a organizar el código en el desarrollo de software? 

10. Seguridad: Explica la diferencia técnica entre "autenticación" y "autorización" en el contexto de seguridad de una aplicación.
La autenticación solo verifica si nuestros datos son válidos, por ejemplo: inicias sesión en una plataforma escolar como alumno.
La autorización verifica que lo que realiza un usuario realmente le pertenezca al mismo, por ejemplo: un alumno no debería tener permisos ni forma de modificar su calificación.
